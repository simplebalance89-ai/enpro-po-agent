# EnPro PO Agent — Complete Data Catalog

**Date:** 2026-06-01  
**Purpose:** Every data element, table, CSV, field, and relationship mapped. This is the source of truth for the data layer rebuild.

---

## Overview: Two Worlds

The system operates between **two data universes**:

```
P21 SQL Server (Source of Truth)
    ├── oe_hdr          (Sales Order headers — 105+ columns)
    ├── oe_line         (Sales Order lines — 100+ columns)
    ├── customers       (Customer master)
    ├── inv_mast        (Item master)
    ├── vendor          (Vendor master)
    ├── po_hdr / po_line (Purchase Order history)
    └── ...
            │  (SO_PULL.sql exports → CSV)
            ▼
Agent Crosswalk CSVs (Working Cache)
    ├── customer_crosswalk.csv      (4,880 rows)
    ├── customer_item_crosswalk.csv (22,675 rows)
    ├── customer_po_history.csv     (23,452 rows)
    ├── item_master_index.csv       (11,911 items)
    ├── customers_p21.csv           (7,833 customers)
    └── customer_defaults.csv       (derived)
            │  (loaded into memory → matching engine)
            ▼
Agent Runtime Data
    ├── PO Store (JSON files — one per PO)
    ├── CISM Batch (accumulated CSVs)
    ├── Audit Log (missing — needs build)
    └── Outbound Sync (JSON files)
```

## 1. P21 SOURCE TABLES (The Authority)

These are the real tables in Prophet 21. The agent pulls from them via `so_pull.sql`.

|--------|------|----------|

| `ship2_add1` | VARCHAR(255) | Address matching |

| `order_date` | DATE | Crosswalk recency |

## 2. AGENT CROSSWALK CSVs (The Brain)

These are generated by `crosswalk_csv_builder.py` from P21 SO exports.

### 2.1 `customer_crosswalk.csv` — 4,880 rows

**Purpose:** Maps ship-to names+addresses to P21 customer IDs.

| Column | Source | Example |
|--------|--------|---------|
| `source_system` | Hardcoded | "P21" |
| `source_customer_id` | Ariba/Coupa org ID | "" (empty for P21 seed) |
| `source_customer_name` | Ariba/Coupa name | "" (empty for P21 seed) |
| `ship2_name` | oe_hdr.ship2_name | "Stepan Chemical Co" |
| `ship2_name_normalized` | `normalize_name()` | "stepan chemical" |
| `ship2_add1` | oe_hdr.ship2_add1 | "100 W Hill St" |
| `ship2_add1_normalized` | `normalize_address()` | "100 w hill st" |
| `ship2_city` | oe_hdr.ship2_city | "Chicago" |
| `ship2_state` | oe_hdr.ship2_state | "IL" |
| `ship2_zip` | oe_hdr.ship2_zip | "60610" |
| `p21_customer_id` | oe_hdr.customer_id | "207620" |
| `p21_customer_name` | oe_hdr.ship2_name | "Stepan Chemical Co" |

## 4. AGENT RUNTIME DATA (PO Store)

### 4.1 PO JSON Files (`data/po_store/`)

Each file is `{intake_id}.json` — a serialized `POPayload` dict.

**Top-level fields:**

| Field | Type | Description |
|-------|------|-------------|
| `intake_id` | string | SHA256 hash of (po_no + source + date) |
| `source` | string | EMAIL, ARIBA, COUPA, PDF, DIRECT |
| `format` | string | cxml, pdf, text |
| `received_at` | string | ISO datetime |
| `status` | string | RECEIVED, PARSED, VALIDATED, PENDING_REVIEW, APPROVED, REJECTED |
| `overall_confidence` | string | green, yellow, red |
| `review_required` | bool | True if yellow/red |
| `classification_confidence` | float | Parser confidence |
| `cism_blob_path` | string | Azure blob path (if uploaded) |
| `header` | dict | `POHeader` object |
| `lines` | list | `POLineItem` objects |
| `raw_content` | string | Truncated raw input |
| `result_data` | dict | Matching results, scores, CISM paths |
| `reviewer` | string | Who approved/rejected |

## 5. DATA RELATIONSHIPS

```
P21 oe_hdr ──┬──► customer_crosswalk (ship2_name + zip → customer_id)
             ├──► customer_po_history (po_no → customer_id + order_no)
             ├──► customer_defaults (customer_id → contact, address, terms, carrier)
             └──► (via oe_line) ──► customer_item_crosswalk (customer_id + part → item)
             
P21 oe_line ──┬──► customer_item_crosswalk (customer_part_number → inv_mast_uid)
              ├──► item_master_index (inv_mast_uid → item desc, part number)
              └──► (price data) → price bounds for anomaly detection

Incoming PO ──┬──► customer_crosswalk (match ship-to → customer_id)
              ├──► customer_item_crosswalk (match part → inv_mast_uid)
              ├──► customer_po_history (dedup check)
              ├──► item_master_index (fallback fuzzy match)
              ├──► customer_defaults (CISM field defaults)
              └──► customers_p21 (display data)

Approved PO ──► learn_from_approval ──► updates customer_crosswalk, customer_item_crosswalk, customer_po_history
```

## 6. DATA QUALITY ISSUES CATALOGED

| Issue | Location | Impact | Fix |
|-------|----------|--------|-----|
| `source_customer_id` empty in all rows | `customer_crosswalk.csv` | Learned exact match (Stage 1) never fires for P21-seeded data | Add Ariba/Coupa org IDs |
| `p21_item_desc` often NULL/empty | `item_master_index.csv` | Fuzzy description matching fails | Pull `inv_mast.item_desc` directly |
| `supplier_name` shows IDs not names | `item_master_index.csv` | Hard to verify item source | Join `vendor` table |
| Price stats never update | `customer_item_crosswalk.csv` | Price anomaly detection uses stale bounds | Recalculate on update |
| No `item_id` (part number) in crosswalk | `customer_item_crosswalk.csv` | Operators see UID, not familiar part number | Add `p21_item_id` column |
| `last_seen` never read | All crosswalks | No recency weighting | Use in scoring |
| `is_active` never checked | All crosswalks | Inactive entries still match | Filter in engine |
| UOM not normalized | `POLineItem` | "EACH", "PCS", "EA" all pass through differently | Build UOM crosswalk |

## 8. WHAT THE BUILDER NEEDS TO BUILD

### 8.1 SQLite Schema (`data_layer/schema.sql`)

Port the Azure SQL schemas to SQLite:
- `po_store` table (replaces JSON files)
- `audit_log` table (new)
- `cism_batch_headers` + `cism_batch_lines` tables (replaces CSV batch)
- `crosswalk_*` tables (mirror of CSVs, with proper types)
- `uom_crosswalk` table
- Indexes on all lookup keys

### 8.2 Data Refresh Job (`data_layer/refresh.py`)

Scheduled job that:
1. Runs `so_pull.sql` against P21 (or reads exported CSVs)
2. Runs `crosswalk_csv_builder.py` to generate new crosswalks
3. Validates new crosswalks (no NULL customer_ids, reasonable row counts)
4. Backs up old crosswalks
5. Atomically swaps new crosswalks in
6. Invalidates engine cache

### 8.3 Migration Script (`data_layer/migrate.py`)

One-time migration:
1. Reads all `data/po_store/*.json` files
2. Inserts into SQLite `po_store` table
3. Creates indexes
4. Validates: count matches, fields match
5. Archives old JSON files (don't delete yet)
